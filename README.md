# Incident Radar

CLI-приложение на Go для анализа NGINX-логов. Читает локальные файлы, glob-маски и HTTP(S)-источники, фильтрует записи по датам и сохраняет статистику в JSON или Markdown.

## Требования

- Go 1.26.6 или новее в пределах ветки 1.26;
- GNU Make — необязательно, команды Go можно запускать напрямую.

Все команды ниже выполняются из корня проекта.

## Быстрый старт

Склонируйте репозиторий и скачайте зависимости:

```bash
git clone https://github.com/thexolod/incident-radar.git
cd incident-radar
go mod download
```

Пример входных данных уже лежит в [example.log](example.log):

```text
192.0.2.1 - - [01/Mar/2025:10:00:00 +0000] "GET /orders HTTP/1.1" 200 100 "-" "curl"
192.0.2.2 - - [01/Mar/2025:10:01:00 +0000] "GET /missing HTTP/1.1" 404 300 "-" "curl"
```

Получить JSON-отчёт:

```bash
go run ./cmd/incident-radar --path example.log --output report.json
```

Получить Markdown-отчёт:

```bash
go run ./cmd/incident-radar --path example.log --format markdown --output report.md
```

Готовый пример JSON-отчёта: [example-report.json](example-report.json).

Существующий output-файл не перезаписывается. Для повторного запуска укажите новое имя выходного файла.

## Аргументы CLI

| Аргумент | Описание |
| --- | --- |
| `--path`, `-p` | Обязательный путь к `.log` / `.txt`, glob-маска или HTTP(S)-URL |
| `--format`, `-f` | Формат отчёта: `json` по умолчанию или `markdown` |
| `--output`, `-o` | Обязательный путь отчёта: `.json` для JSON, `.md` для Markdown |
| `--from` | Необязательная начальная дата `YYYY-MM-DD`, включительно |
| `--to` | Необязательная конечная дата `YYYY-MM-DD`, включительно |

При двух указанных границах требуется `from < to`. Формат отчёта должен соответствовать расширению output-файла. Родительская директория output должна существовать.

### Примеры команд

Прочитать несколько файлов по маске. Кавычки передают glob самой программе:

```bash
go run ./cmd/incident-radar --path "sample_logs/*.txt" --output combined.json
```

Ограничить период:

```bash
go run ./cmd/incident-radar --path example.log --from 2025-03-01 --to 2025-03-03 --output period.json
```

Использовать короткие флаги:

```bash
go run ./cmd/incident-radar -p example.log -f markdown -o short.md
```

Прочитать HTTP-источник с помощью тестового сервера проекта:

```bash
# Терминал 1
go run ./cmd/log-server --port 8000

# Терминал 2
go run ./cmd/incident-radar --path http://127.0.0.1:8000/access.txt --output remote.json
```

## Обработка логов и фильтрация

Поддерживается формат NGINX combined. Из записи извлекаются IP-адрес, пользователь, время с часовым поясом, HTTP-метод, ресурс, протокол, код ответа, размер ответа, Referer и User-Agent.

Повреждённые строки пропускаются с предупреждением в stderr; обработка остальных строк продолжается:

```text
WARN: skipped malformed log line
```

Без `--from` и `--to` учитываются все корректные записи. Можно указать только одну границу. Обе заданные даты входят в период целиком.

Даты CLI интерпретируются в UTC. Время записи сравнивается с границами с учётом часового пояса из лога. Внутри используется полуинтервал `[from 00:00, следующий день после to 00:00)`: например, `--to 2025-03-03` включает весь день 3 марта UTC и исключает начало 4 марта.

Источники читаются построчно через `bufio.Scanner`, лимит токена — 1 МиБ. Исходные логи целиком в память не загружаются. Для точного p95 сохраняются размеры всех учтённых ответов, поэтому память для статистики размеров растёт пропорционально числу записей.

## Статистика и отчёты

Общая статистика собирается по всем обработанным источникам и корректным записям, прошедшим фильтр:

- список файлов или URL;
- общее число запросов;
- средний, максимальный размер ответа и p95 в байтах;
- top-10 ресурсов;
- количество запросов для каждого HTTP-кода.

Ресурсы сортируются по убыванию числа запросов. При равенстве — по пути в лексикографическом порядке по возрастанию. Если ресурсов меньше десяти, включаются все.

Средний размер рассчитывается дробным делением суммы размеров на число запросов и округляется до двух знаков после запятой.

Для p95 используется nearest-rank: размеры сортируются по возрастанию, выбирается элемент с индексом `ceil(0.95 * N) - 1`, где `N` — число учтённых запросов. Для размеров `1…20` p95 равен `19`.

Если подходящих записей нет, число запросов, средний размер, максимум и p95 равны нулю, top ресурсов пуст.

JSON и Markdown содержат одинаковые данные. Отчёт создаётся после успешного чтения источников; запись выполняется с запретом перезаписи существующего файла.

### Пример JSON

Для `example.log` из быстрого старта:

```json
{
  "resources": [
    {"path": "/missing", "count": 1},
    {"path": "/orders", "count": 1}
  ],
  "totalRequestsCount": 2,
  "responseCodes": {
    "200": 1,
    "404": 1
  },
  "files": ["example.log"],
  "responseSizeInBytes": {
    "average": 200,
    "max": 300,
    "p95": 300
  }
}
```

### Пример Markdown

```markdown
# Анализ NGINX-логов

| Метрика | Значение |
| --- | ---: |
| Всего запросов | 2 |
| Средний размер ответа, байт | 200.00 |
| Максимальный размер ответа, байт | 300 |
| p95, байт | 300 |

## Источники

| Файл или URL |
| --- |
| example.log |

## Ресурсы

| Ресурс | Количество запросов |
| --- | ---: |
| /missing | 1 |
| /orders | 1 |

## Коды ответа

| Код | Количество запросов |
| ---: | ---: |
| 200 | 1 |
| 404 | 1 |
```

## Коды завершения

| Код | Значение |
| ---: | --- |
| `0` | Успешная обработка и сохранение отчёта |
| `1` | Внутренняя ошибка, ошибка сериализации или сохранения отчёта |
| `2` | Ошибка аргументов, ожидаемая ошибка источника или существующий output |

Примеры ошибок с кодом `2`: обязательный аргумент не указан, неверный формат или дата, `from >= to`, несовпадение расширения и формата, отсутствие подходящих файлов, недоступный URL, HTTP 404, существующий output-файл.

Невозможность создать отчёт из-за отсутствующей родительской директории приводит к коду `1`. Диагностика и предупреждения выводятся в stderr.

Для проверки exit codes запускайте собранный бинарник: `go run` может возвращать собственный код завершения.

Linux:

```bash
go build -o bin/incident-radar ./cmd/incident-radar
./bin/incident-radar --path example.log --output built.json
echo $?
```

Windows PowerShell:

```powershell
go build -o bin/incident-radar.exe ./cmd/incident-radar
.\bin\incident-radar.exe --path example.log --output built.json
$LASTEXITCODE
```

## Проверки

```bash
go test ./...
```

Unit-тесты проверяют чтение источников, парсинг, фильтрацию дат, статистику, JSON/Markdown и сохранение файла без перезаписи.

E2E-тест собирает CLI и запускает его в отдельном процессе. Проверяются создание JSON и Markdown, коды завершения `0`, `1`, `2` и сохранность существующего output-файла.

Запустить только E2E:

```bash
go test ./cmd/incident-radar -run '^TestCLI$' -v
```

Команды Makefile:

```bash
make format
make check
make test
make test-race
```

`make check` проверяет зависимости, форматирование и линтеры. `make test` запускает тесты и создаёт `coverage.out` и `coverage.html`. Для `make test-race` нужны поддержка CGO и C-компилятор.
